## Challenge Overview

Provided: `data.json` with a prime p, 16 factors, a target hash, and an encrypted flag.

The hash is a **modular subset sum**:

```
hash = Σ (factors[i] × xᵢ) mod p
```

Where each `xᵢ` is a byte (0–255). The flag is AES-ECB encrypted with the 16-byte preimage as key.

## Vulnerability

The modular knapsack problem is NP-hard in general — but this instance is weak:
- Only n=16 unknowns
- Small coefficients (8-bit values, 0–255)
- Large modulus p (137 bits)

This ratio makes it solvable via **Lattice Reduction** (Closest Vector Problem).

## Solution: Balanced Lattice + LLL + Babai

Construct an (n+1)×(n+1) matrix. Apply a large scaling weight K=2^160 to enforce the modular constraint:

```
L = | 1  0  ...  0   K·f₀ |
    | 0  1  ...  0   K·f₁ |
    | ...                  |
    | 0  0  ...  1   K·f₁₅|
    | 0  0  ...  0   K·p  |
```

Target vector:

```
T = (128, 128, ..., 128, K·h)
```

Find the closest vector to T in the lattice — recovers the xᵢ values.

Implemented in **SageMath** using LLL + Babai's Nearest Plane algorithm.

## Conclusion

LLL transforms an apparently intractable search space of 256^16 down to a single matrix reduction taking under a second. When you see a modular linear combination of small unknowns, think lattice.
